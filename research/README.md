# 研究记录与证据规范

本目录保存用于行程判断的原始线索、可变信息快照和研究方法。面向旅客的总结与报告用中文维护；`AGENTS.md` 等执行规则可以用英文，机器字段名、网址和来源原名保留原文。

## Agent 开始与结束工作

1. 先读项目根目录的 `AGENTS.md`、`CONTEXT.md`、`README.md` 和本页。
2. 按任务再读对应的 `trip/` 分类页、城市指南或研究页。添加记录前，先查本页和现有数据表，避免重复。
3. 价格、库存、班次、开放时间和政策等动态信息写入对应研究表，并在旅程决策页引用 `record_id`；稳定偏好和已确认事实写入 `CONTEXT.md`。
4. 有实质进展时更新根目录 `README.md`。交接说明要指出改动文件、来源局限和仍待核实事项。不要把搜索线索写成已选择、已预订或官方确认。

## 目录职责

| 位置 | 主要用途 |
|---|---|
| `../CONTEXT.md` | 已确认事实、规划假设、约束和待决事项 |
| `../trip/` | 筛选条件、候选比较、决策理由和行程安排；不堆放逐次搜索历史 |
| `flights/`、`accommodation/` | 逐次机票和房价查询快照；每行是一条可辨认的观察 |
| `xhs/` | 小红书原始灵感与逐篇研究记录；不能作为营业、票价、安全或交通的最终依据 |
| `city-maps/` | 地图接口、中文地图查看器和官方地图文件；当前数据状态见该目录 README |
| `archive/` | 迁移前或被替换文档的只读历史副本，不是当前事实源 |
| `../destinations/` | 已整理成旅客可执行的城市指南，并注明动态事实的来源和日期 |
| `../visualizations/` | 从结构化记录生成的图表和报告；不是新的事实源 |

## 证据状态与决策状态

每条可变信息分别记录以下两个状态，不得混成一个“已核实/已选择”字段。

| 字段 | 可用值 | 含义 |
|---|---|---|
| `evidence_status` | `unverified` | 信息来自旧笔记、无直接链接、条件不完整或尚未复核；不能据此作最终推荐 |
| `evidence_status` | `source_checked` | 在所记来源页面看到该条信息；OTA 搜索卡只证明页面显示过，不证明承运人政策或房东条款 |
| `evidence_status` | `officially_verified` | 已在负责运营的航空公司、住宿方、政府或景点官方来源核实；记录具体页面 |
| `evidence_status` | `expired` | 曾有来源，但价格、库存、时刻或规则已过期；保留历史，不再表示当前可用 |
| `decision_status` | `idea` | 用于探索的方向、邻近月份参照或未满足条件的线索 |
| `decision_status` | `candidate` | 当前仍值得比较且关键条件已满足；搜索结果仍不是预订 |
| `decision_status` | `selected` | 旅客明确选定的方案，尚未因此代表已经预订 |
| `decision_status` | `booked` | 仅在实际完成预订后使用，并写入可核实的确认信息；没有用户明确授权时不得执行预订 |
| `decision_status` | `rejected` | 因预算、路线、行李、取消政策或旅客决定等原因不再作为方案；在备注中写明理由 |

核验状态与决策状态彼此独立。例如，超预算结果可为 `source_checked` + `rejected`；旧的邻月价格可为 `unverified` + `idea`。

## 动态信息记录规则

- 每条价格、库存、班次、开放时间或政策记录应有唯一 `record_id`、来源名称、来源类型、直接来源链接和 `checked_at_hkt`。时间用 ISO 8601 和香港时区偏移，例如 `2026-09-25T14:30:00+08:00`。
- 若旧笔记只保留了日期，写 `2026-09-25`；若没有可靠查询时间或直接链接，就留空，不要补造精度。缺少来源链接或关键条件的旧记录标为 `unverified`，在备注中说明缺口。
- 每次新查询追加一行，不覆写旧价格。查询失效时，将该行的证据状态改为 `expired` 只适用于已确认该记录不再有效的情况；保留历史金额与条件。
- 用原始币种记录平台显示金额；换算价须注明汇率日期、汇率方向与来源，并与原币金额分开。未知税费、乘客数、床型、免费取消期限等留空，不能填 `0` 或凭经验推断。
- 报价页、OTA 和社交内容属于线索；机场甩尾、行李提取、退改规则和运营事实要找实际承运人或服务提供方核实。不得将 OTA 页面显示的行李重量等同于承运人对提前提取行李的承诺。

## 机票与住宿快照

- [机票票价快照](flights/fare-snapshots.csv)：一行对应一组明确的搜索条件和一条价格观察。`observation_role` 区分实际行程搜索、邻近月份参照和市场基准；这些类别不可混成同一条趋势线。只有查询条件可比时才计算价差。
- [机票特价结构研究](flights/fare-patterns.md)：记录多程、开口程、甩尾、错误票价和漏油线索的风险分级、来源核验与后续监测矩阵；不把社区经验当作出票事实。
- [住宿房价快照](accommodation/rate-snapshots.csv)：一行对应一个住宿、房型、入住日期、入住人数和取消条件。相同酒店的不同房型/取消政策分别记录。
- 机票表先记录平台页面实际显示的 `displayed_amount_as_shown`，再用 `amount_basis` 标注 `per_person`、`group_total` 或 `unknown`。只有口径明确时才填 `displayed_amount_per_person` 或 `displayed_total_amount`；未知时留空，不推算。金额均使用 `currency` 表示。`search_filters` 和 `baggage_filter_scope` 记录平台筛选；筛选不等于逐段确认了公斤数。
- 机票表的 `observation_role` 使用 `trip_option`、`adjacent_month_reference` 或 `market_reference`；`baggage_filter_scope` 使用 `displayed_both_legs`、`outbound_only` 或 `not_recorded`；布尔值写小写 `true` / `false`。不适用写 `not_applicable`，未知值留空或按相应状态列写 `unknown`。
- 机票方案可来自普通往返、开口、多程、漏油/异常低价或甩尾等搜索结构。每位旅客必须记录覆盖完整去程与返程的最终可支付总价；多张票组合要逐张列价、求和并标明独立出票及自助衔接，不能把单段或未含行李的低价写成全程合格价。每个实际搭乘航段须有至少 20 kg 托运行李，或把加购费计入总价。返程经北京甩尾时，另记录承运人是否同意在北京提前提取行李及行李牌终点；未知则不得作为已确认条件。
- 只有 `decision_status=candidate` 且日期、旅客数、完整路线、各实际搭乘航段行李、税费和主要票规足以对比的记录，才进入候选比较。邻月参照只能用于观察价格变化，不能声称目标日期可买到该价格。
- 住宿须按具体房型记录三人入住、床型、总价、税费和免费取消截止时间。未确认入住日期或房型的参考价不得当作可预订候选。

## 地图与可视化

- 地图长期展示数据入口是 `city-maps/city-data.js`；`city-atlas.html` 读取该文件展示地图。地图要素用 `evidence[].record_id` 引用本目录中的研究记录；地图数据是展示适配层，不替代研究原始记录。临时导入页面的 GeoJSON 刷新即消失。
- `city-maps/three-cities-orientation.kml` 是空城市目录模板。地图页面可从当前数据导出 KML，但导出文件是衍生物，不是长期源数据。
- 地图要素不得因图层类型而自动推导推荐、安全等级或危险区域；展示内容由研究记录支持。已停止维护的旅行速查只在 `archive/` 留存，不作为当前指南。
- 图表和报告应记录输入文件/记录编号、生成日期、筛选条件、币种和换算方式。没有足够且可比的时间点时，明确写“样本不足”，不要画出或暗示价格趋势。
- 修改图表前先更新结构化数据和生成说明；确认输出没有把 `idea`、`unverified` 或 `expired` 记录误画成当前推荐。
